# 后续 iPad 版路线

本轮没有创建 iPad 工程或运行移动构建。Rust 入口已拆成桌面 `main.rs` 与共用 `lib.rs`，后者保留 `#[cfg_attr(mobile, tauri::mobile_entry_point)]` 和移动链接所需 crate 类型。

以后确认要做时，在安装完整 Xcode、对应 SDK 和 Rust iOS targets 的 Mac 上，先确认正式 identifier 与开发团队，再在 `app/` 执行：

```sh
npm run sync
npx --no-install tauri ios init
npx --no-install tauri ios dev
```

初始化会产生原生工程；届时按 Tauri/Xcode 生成结果配置 iPad 支持、横屏方向、最低系统版本、签名与测试设备，不直接沿用 Mac 的窗口限制。模拟器通过后再在真机上测，最后另行授权发行构建、TestFlight 或上架。

## 必须验证和调整的交互

触屏没有悬停，手指会挡住道具。逐关验证按下、拖动、吸附、松手、拖出画布、系统打断与多指触摸。当前画布已禁用浏览器触摸滚动/选中，拖拽跟随起始指针并在失焦时取消；这只是兼容准备，不等于触屏验收通过。不能以鼠标测试替代手指测试。

第一关礼物与第二关文件夹沿用游戏自身时间窗口判断双击，不依赖浏览器 `dblclick`。真机需确认两次轻点可识别、单次轻点不误判，且不会触发页面缩放。是否为触屏修改双击教学与提示属于后续玩法决定，本轮没有修改双击时间或教学内容。

课堂内容还有方向键、Enter、Esc 等键盘交互。应测试无外接键盘时现有画面控件是否足够，确认是否需要新的触屏入口；大人快捷键在没有键盘时不可用，其替代方案另行设计，不能直接把重置按钮放到孩子画面。

## 布局、声音与数据

按横屏宽高比 1.33–1.43 测试，覆盖不同 iPad、分屏和旋转恢复。沿用 FIT 保留完整 1280×800 玩法区；检查背景填充、HUD、任务牌与拖放目标。入口已有 `viewport-fit=cover`，后续必须读取 `env(safe-area-inset-*)` 为系统边缘与底部手势条预留空间，不能把现有桌面适配当成已实现 iPad 安全区。

本地字体要在 WKWebView 加载后再画入 canvas；音效仍只在首次手势后恢复。验证前后台切换、锁屏返回、系统音量、静音开关与音频中断后的恢复。存档仍考虑本地 `island2:v1`，分别验收退出重启和更新保留；卸载后数据不保证保留，Mac 与 iPad 不自动同步。
