# 后续签名与公证

本轮未执行签名、公证、账号登录或分发。以下是以后获得授权后的工作顺序，不包含账号资料。

1. 先确认正式 bundle identifier、显示名称和版本号，再决定分发方式。直接分发 Mac App 通常走 Developer ID 签名与公证；Mac App Store 是另一套提交流程，不混用。
2. 由有权限的人在 Mac 钥匙串准备有效的 Developer ID Application 证书及其私有部分，核对归属团队。不要把任何凭据、导出证书或认证资料写进仓库。
3. 按届时 Tauri 2 文档配置签名身份及 hardened runtime，审核所需 entitlements。游戏不需要额外访问能力，不为了通过构建添加无关 entitlement。正式签名配置应单独审阅，本轮配置保持无签名身份。
4. 构建 Apple 芯片发行包，使用系统签名验证工具确认 `.app` 的签名和嵌套组件完整。由授权人员通过本机安全存储完成公证认证，再使用 Tauri 的公证流程或 `xcrun notarytool` 提交适用的分发产物，等待成功结果并检查日志。
5. 使用 `xcrun stapler` 为可装订的 App/DMG 附上票据并验证，使用 `spctl` 检查系统评估结果。只分发最终验证通过的产物。
6. 在另一台 Mac 上按真实下载路径安装并离线打开，确认没有首次打开拦截、能通关、字体音效正常、存档可保留。记录产物版本与校验值；以后每个新版本都重新签名、公证和验证。

这些步骤尚未实测；具体工具选项应在实际执行时按安装版本核对。本文件不授权使用任何账号或发布产物。
